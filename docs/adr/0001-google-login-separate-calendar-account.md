# 구글 전용 로그인, 캘린더 연동은 별도 구글 계정, Better Auth 사용

로그인은 구글 계정으로만 하고, 캘린더 읽기 권한은 로그인할 때가 아니라 캘린더 연동 단계에서 따로 받는다. 이때 로그인 계정과 다른 구글 계정을 연동할 수 있게 했다. 개인 Gmail로 로그인한 학생도 학교 계정(Google Workspace)의 일정을 불러올 수 있어야 하기 때문이다. 이 구조를 기본 기능으로 지원하는 라이브러리가 Better Auth뿐이라 Better Auth를 쓴다. 같은 제공자의 다른 이메일 계정을 연결할 수 있고, 계정별로 토큰을 저장하며, 토큰을 자동으로 갱신해 준다.

## Considered Options

- **로그인할 때 캘린더 권한까지 한 번에 받기**: 흐름은 가장 단순하다. 하지만 첫 화면부터 캘린더 동의를 요구하게 되고, 로그인 계정의 캘린더만 쓸 수 있다.
- **Auth.js v5**: 아직 정식 버전이 없고, 보안 수정만 하는 유지보수 모드다. 다른 계정 연동과 토큰 갱신을 지원하지 않아서, 캘린더 연동 흐름 대부분을 직접 만들어야 한다.

## Consequences

- 사용자 한 명에게 구글 계정 연결이 두 개(로그인 계정, 캘린더 연동 계정) 생길 수 있다. 캘린더 토큰은 반드시 캘린더 연동 계정의 연결에서 꺼내야 한다.
- Better Auth는 토큰을 암호화하지 않은 채 저장하고, 구글 권한 철회도 자동으로 하지 않는다. 그래서 토큰 암호화, 그리고 탈퇴와 연동 해제 때의 권한 철회는 직접 구현한다.
- 구글 앱은 테스트 상태로 운영한다. 그래서 테스트 사용자로 등록한 사람만 쓸 수 있고, 캘린더 토큰이 7일마다 만료되어 재연동 안내가 자주 뜬다.
