# 추천받을 옷 구분

Status: resolved

## Problem Statement

앱은 사용자가 어떤 옷을 추천받고 싶은지 모른다. 그래서 남성복을 입는 사용자에게도 새 옷 후보로 원피스가 나온다(구매 추천, 이 한 벌 제안, 한 벌만 더하면, 구매 대화).

## Solution

사용자에게 **추천받을 옷 구분**(남성복 / 여성복)을 묻는다. 고르기 전에는 거르지 않는다.
- 새 옷을 제안하는 LLM에게 알려 준다.
- "남성복"이면 앱 규칙으로도 원피스 새 옷을 뺀다.
- 이미 옷장에 등록한 옷은 구분과 상관없이 그대로 쓴다.

## User Stories

1. 사용자로서, 온보딩에서 남성복·여성복 중 무엇을 추천받을지 고르고 싶다.
2. 사용자로서, 설정에서 언제든 바꾸고 싶다.
3. 이미 가입한 사용자로서, 메인 화면에서 한 번 안내를 받고 바로 고르고 싶다.
4. 남성복을 고른 사용자로서, 새 옷 제안·구매 추천·구매 대화 어디서도 원피스를 보고 싶지 않다. "원피스로"라고 말해도 마찬가지다.
5. 사용자로서, 내가 등록한 옷은 구분과 상관없이 계속 추천에 쓰이기를 원한다.

## Implementation Decisions

- **옷장 모듈:** 선호 색상·스타일 표에 추천받을 옷 구분(`menswear`/`womenswear`)을 둔다. 고르지 않았으면 없음이고, 거르지 않는다. 읽기·저장을 둔다. 목록 밖 값은 거부한다.
- **새 옷 후보 어댑터:** 선호와 함께 구분을 받는다. 지시문에 반영한다.
- **규칙:** 남성복이면 다음에서 원피스를 뺀다. 여성복이나 고르지 않은 사용자는 거를 종류가 없다.
  - 구매 추천과 구매 대화, 한 벌만 더하면: 새 옷 후보
  - 전부 새 옷 코디: 원피스가 든 코디
  - 이 한 벌 제안: 후보
- **화면:**
  - 온보딩 선호 단계와 설정의 선호 폼에 "추천받을 옷"을 둔다.
  - 고르지 않은 사용자에게는 메인 화면에 고르는 카드를 둔다.

## Testing Decisions

- 옷장 모듈: 저장·읽기와 기본값 없음, 목록 밖 값 거부.
- 추천 모듈: 남성복이면 구매 추천·전부 새 옷·구매 대화·한 벌만 더하면에 원피스 새 옷이 없음. 고르지 않았으면 원피스도 나올 수 있음. 어댑터가 구분을 받음.
- 이 한 벌 제안: 남성복이면 원피스 후보가 빠짐.

## Out of Scope

- 사진 분석이 옷의 구분을 판단하기
- 원피스 외의 옷(예: 스커트)을 구분하기: 지금 옷 종류에 없다.
