# 구매 대화

Status: resolved

## Problem Statement

구매 추천 코디는 한 번 보여 주면 끝이다. 사용자는 "바지 말고 아우터로", "좀 더 밝은 색으로", "내 네이비 셔츠랑 어울리게"처럼 새로 살 옷에 바라는 점이 있어도 말할 곳이 없다. 메인 추천에는 대화로 수정하기가 있는데 구매 추천에는 없어서 경험이 끊긴다.

## Solution

구매 추천 화면에 대화창을 둔다. 사용자가 말하면 AI가 그 말을 **구매 조건**으로 바꾸고, 그 조건으로 구매 추천 코디를 다시 고른다. 결과 위에는 AI 비서처럼 말하는 **비서 답장**이 한두 문장 붙는다.

- 새 옷은 꼭 필요한 만큼만 넣는다. 사용자가 종류를 여럿 말하거나("바지랑 신발 둘 다 새로") 전부 새로 해 달라고 하면 그만큼 새 옷으로 바꾼다.
- 메인 추천처럼 조건이 쌓이고, 이전 단계나 처음 구매 추천으로 되돌릴 수 있다.
- 쇼핑 링크는 여전히 없다.

## User Stories

1. 사용자로서, 구매 추천 화면에서 말로 새 옷의 종류를 바꾸고 싶다("아우터로 추천해 줘"). 그래야 필요한 종류를 본다.
2. 사용자로서, 새 옷의 색 방향(더 밝게·더 어둡게)이나 특정 색, 소재를 말하고 싶다. 그래야 취향에 맞는 옷을 본다.
3. 사용자로서, 더 캐주얼하게·더 포멀하게를 말하고 싶다.
4. 사용자로서, 내 옷 중 꼭 입을 옷("내 네이비 셔츠랑 어울리게")이나 빼고 싶은 옷을 말하고 싶다.
5. 사용자로서, 보여 준 새 옷이 마음에 들지 않으면 "이 바지 말고"로 빼고, 마음에 들면 "이 니트는 좋아"로 남기고 싶다.
6. 사용자로서, 원하면 새 옷 여러 벌("바지랑 신발 둘 다 새로", "전부 새 옷으로")로 된 코디도 보고 싶다.
7. 사용자로서, 말하지 않았는데 새 옷이 여러 벌 섞이지 않기를 원한다.
8. 사용자로서, AI가 비서처럼 무엇을 왜 바꿨는지 짧게 말해 주기를 원한다. 그 말은 실제 결과에 있는 사실만 담아야 한다.
9. 사용자로서, 조건이 대화 동안 쌓이고, 지금 걸린 조건을 보고 싶다.
10. 사용자로서, 한 단계 전이나 처음 구매 추천으로 되돌리고 싶다.
11. 사용자로서, 코디와 관계없는 말, 알 수 없는 옷, 맞는 코디가 없는 조건, AI 실패에는 결과를 그대로 두고 이유를 듣고 싶다.
12. 사용자로서, 구매 추천 대화가 메인 추천의 대화 이력을 지우지 않기를 원한다.

## Implementation Decisions

- **코디 추천 모듈 (기존 경계)에 추가:** 구매 추천이 **구매 추천 세션**을 시작한다. 새 입구는 `revisePurchase`(메시지), `undoPurchase`(단계), `latestPurchase`(세션)다. `purchaseOutfits`의 결과에 세션 id, 단계, 대화(메시지·조건·답장), 반영 못 한 이유가 붙는다.
- **구매 조건:**
  - 새 옷의 종류. 하나 또는 여럿, 또는 전부.
  - 색 방향(밝게·어둡게) 또는 특정 색.
  - 소재.
  - 스타일 방향(격식 한 단계).
  - 가진 옷 고정·제외.
  - 보여 준 새 옷 남기기·빼기.
  - 무관한 메시지.
  - 세션 동안 쌓인다. 같은 종류의 조건이나 같은 옷에 대한 조건은 나중 것이 이긴다.
- **LLM의 역할:** 말을 구매 조건으로 바꾸는 일과 비서 답장을 쓰는 일만 한다. 코디는 점수 규칙이 고른다.
- **코디 고르기:**
  1. 후보 풀은 세션에서 지금까지 받은 새 옷 후보다.
  2. 새 옷은 그날의(스타일 방향이 반영된) 격식 수준과 같아야 한다. 색·소재 조건도 지켜야 한다. 남긴 새 옷은 예외다.
  3. 가진 옷과 비슷한 후보는 버린다. 정리한 옷과 비슷하면 되돌리기로 바꾼다.
  4. 종류를 말했으면 새 옷은 정확히 그 종류들이다. 말하지 않았으면 가장 적은 수(최소 1벌)다.
  5. 점수 순으로 새 옷 조합이 겹치지 않게 최대 3개를 고른다.
  6. 3개가 안 되면 조건을 붙여 LLM에게 후보를 더 받아 풀에 더하고 다시 고른다.
- **반영 못 함:** 결과를 그대로 두고, 단계를 쌓지 않으며, 이유를 돌려준다.
  - 무관한 메시지
  - 알 수 없는 옷
  - 더 갈 수 없는 스타일 방향
  - 맞는 코디 없음
  - LLM이 말을 읽지 못함
- **비서 답장:** LLM이 사실(요청, 조건, 새 옷 이름과 새로 어울리는 가진 옷 수)만으로 한두 문장을 쓴다. 실패하면 템플릿 문장을 쓴다.
- **세션 저장:** 추천 세션 표에 세션 종류(`outfit`/`purchase`)를 더한다. 같은 날짜의 구매 추천 세션은 메인 추천 세션을 지우지 않는다. 옷장 분석은 메인 추천 세션만 본다.
- **결과 모양:** 구매 추천 코디마다 더한 옷 목록을 갖는다. 새 옷은 가상의 옷이다. 가상의 옷과 정리한 옷마다 새로 어울리는 가진 옷의 수가 붙는다. 전부 새 옷 코디도 같은 모양이다.
- **화면:** 구매 추천 화면에 다음을 둔다.
  - 대화창
  - 비서 답장 말풍선
  - 걸린 조건
  - 되돌리기 버튼
  - 반영 못 한 이유 안내

  세션은 URL(`session`)로 이어 간다.

## Testing Decisions

- **추천 모듈 테스트**(`purchase-chat.test.ts`): 하네스, 가짜 LLM, 가짜 한 벌 후보 어댑터로 확인한다.
  - 종류·색·소재·스타일 조건을 지킨다.
  - 가진 옷 고정을 지킨다.
  - 새 옷 빼기를 지킨다.
  - 여러 벌 요청을 반영하고, 말하지 않으면 1벌이다.
  - 후보가 모자라면 조건을 붙여 LLM에게 더 받는다.
  - 조건이 쌓이고 되돌릴 수 있다.
  - 반영 못 하면 결과와 단계가 그대로다.
  - 답장은 LLM 문장이고, LLM이 실패하면 템플릿이다.
  - 메인 추천 세션이 남는다.
- 선례: `revision.test.ts`, `purchase.test.ts`.

## Out of Scope

- 채팅 기록이 쭉 쌓이는 채팅창 화면 (나중에 메인과 함께)
- 쇼핑 링크·가격 (수익 모델이 정해지면)
- 구매 추천 코디 수락("입을게요")

## Comments

- 구현 중 정한 것:
  - 구매 대화의 스타일 방향은 메인 추천과 달리 격식 기울기에 세지 않는다. 사려는 옷에 대한 말이라 평소 코디 취향과 섞지 않는다.
  - 그날 격식 수준이 정해지지 않은 날의 스타일 방향은 처음 구매 추천 코디의 가장 흔한 격식 수준에서 움직인다.
